## Overview

CineMatch AI is a conversational chatbot that understands natural-language
movie/TV preferences, remembers them across turns, and returns **personalized,
explainable recommendations** — generated by a real recommendation engine
(semantic search + hybrid ranking), not by the LLM hallucinating titles.

## Problem Statement

Most simple chatbot demos send the user's prompt straight to an LLM. That has
two problems: the LLM *invents* titles, ratings and facts, and it has no real
notion of "similarity" or structured preference state. CineMatch AI solves this
with a proper retrieval + ranking pipeline where **Claude only explains** what
the engine actually computed.

## Features

- 💬 Conversational memory (Streamlit session state)
- 🧠 Structured preference extraction (Claude + Pydantic + rule-based fallback)
- 🚫 Active negative-preference handling ("I don't like horror")
- 🔍 Semantic search over combined metadata text (Sentence Transformers + FAISS)
- 🎯 Hybrid, weighted, explainable ranking
- 📺 Movie + TV support (local metadata dataset, no per-query TMDB dependency)
- 🖼️ TMDB enrichment (posters, trailers) with caching/retries/rate-limit handling
- 🛡️ Graceful degradation when any external API or artifact is missing
- 🧪 Full pytest suite (LLM & TMDB mocked), evaluation script (P@K, R@K, Hit@K, NDCG@K)
- 🐳 Docker + docker-compose

## How the AI Works

1. **Preference extraction** — Claude converts free text into
   `UserPreferences` (Pydantic-validated JSON). Invalid JSON is recovered and a
   rule-based extractor (regex/heuristics) handles offline mode.
2. **Memory** — new preferences are *merged* with the conversation's existing
   state (dedup lists, later values override scalars, negations accumulate).
3. **Retrieval** — the merged preferences are used to embed a query and/or
   "similar to" titles, then search the FAISS index.
4. **Hard filtering** — content type, excluded genres, min rating, year range,
   runtime bounds, languages, actors/directors, family-friendly are enforced.
5. **Hybrid ranking** — weighted combination of semantic, preference, rating,
   popularity and freshness components (normalized per pool).
6. **Explanation** — Claude explains the top-K **using only supplied data**;
   every card also shows verified "why this matches you" reasons computed from
   real metadata.

```

    ↓

    ↓

    ↓

    ↓

```

## Hybrid Ranking

```
final_score =
    0.50 * semantic_similarity
  + 0.20 * preference_match
  + 0.15 * rating_score
  + 0.10 * popularity_score
  + 0.05 * freshness_score
```

- `semantic_similarity` — normalized FAISS cosine similarity.
- `preference_match` — fraction of applicable preference constraints satisfied.
- `rating_score` — linear ramp from the user's minimum rating to 10.
- `popularity_score` — min-max normalized popularity.
- `freshness_score` — recency relative to the newest title in the candidate pool.

All components are min-max normalized before combining. Weights live in
`config/settings.py` and can be overridden per call.

## Dataset Setup

The project ships a bundled curated sample
(`scripts/generate_sample_data.py`) so it demos out of the box. To use your own
TMDB-style export:

1. Drop a CSV at `data/raw/movies_metadata.csv` with columns
   `id, title, overview, genres, keywords, cast, director, rating, popularity,
   release_date, runtime, language, content_type` (list columns pipe-separated).
2. Run the preparation pipeline:

```bash
python scripts/prepare_data.py
```

This cleans missing values, normalizes genres/cast/director, derives release
years and builds the combined searchable text. Output:
`data/processed/processed_movies.csv`.

## Embedding Generation

```bash
python scripts/build_index.py
```

This embeds every `combined_text` document in batches (default 32) using
`all-MiniLM-L6-v2` and saves `artifacts/embeddings.npy`. Embeddings are
generated **once** and reused at startup.

## FAISS Index Generation

`scripts/build_index.py` also builds and persists:

```
artifacts/faiss.index      # FAISS IndexFlatIP (384-dim, normalized)
artifacts/metadata.pkl     # row metadata aligned with the index
```

If the index is missing the app shows a friendly "run these commands" message
instead of crashing.

## Evaluation

```bash
python scripts/evaluate.py --k 5
```

Metrics (averaged over query titles):

- **Precision@K** — fraction of relevant items in the top-K.
- **Recall@K** — fraction of all relevant items captured in the top-K.
- **Hit Rate@K** — 1 if at least one relevant item appears in the top-K.
- **NDCG@K** — discounted cumulative gain normalized by the ideal ranking.

**Methodology**: relevance is defined on the local dataset as *sharing at
least one genre with the query title while matching its content type*; the
top-K from `recommend(similar_to=[query])` is scored against that set. Swap in
a richer relevance definition (keywords, human judgments, hold-out ratings) as
needed.

Sample output (bundled 117-row sample):

```
  precision@k    0.5600
  recall@k       0.0691
  hit_rate@k     1.0000
  ndcg@k         0.6153
```

## Future Improvements

- Two-tower (user/movie) collaborative filtering blended into the score.

- Streaming responses, thumbs-up/down feedback loop.
- Unit tests for the UI helpers; integration tests with a live TMDB sandbox.

## Limitations

- The bundled dataset is a small curated sample — real breadth requires a full
  TMDB export or Kaggle TMDB 5000 dataset (see Dataset Setup).
- Claude is only as good as the engine: it explains, never invents.
- `sentence-transformers` downloads the MiniLM model on first run (network).
- Poster/trailer enrichment requires a TMDB API key.
- Conversation memory is in-memory only (per session), by design.
